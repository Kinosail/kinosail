# CI/CD reset — 2026-09-22

The workflow directory was cleared and rebuilt from zero. Four Actions files remain because each has one distinct boundary:

1. `ci.yml` is the only PR, merge queue, main, and weekly entry point. It computes one conservative selection plan, runs repository and security checks, calls selected app suites, and exposes the four protected check names. Documentation checks and Pages deployment live here.
2. `app.yml` runs the selected Player or Subtitles suite. Lint, quick Go tests, Go vulnerability checks, production-container checks, a Chromium browser smoke, installer checks, and Player Swift compilation run as relevant. Weekly and manual deep runs execute race/coverage and the complete browser suite across Chromium, Firefox, and WebKit. Its jobs read the plan directly, without a serial selection runner. The final app check validates the plan and fails closed on missing, cancelled, failed, or unexpected skips.
3. `publish.yml` accepts only the same main run's four successful required results. It builds affected apps on AMD64 and ARM64, tests and scans by digest, signs, attests, and promotes without rebuilding. Per-app promotion is serialized and rejects stale main commits.
4. `release.yml` handles both independent version tags. It requires successful CI for the exact main commit, then builds and signs versioned images and installer archives. It writes only the exact version tag, so older releases cannot roll back continuous `latest` or a mutable minor tag.

The selector treats unknown, workflow, shared, renamed, and deleted inputs conservatively. Documentation source changes select the docs build without unrelated server suites. Required checks are always emitted, including for intentionally skipped apps. The workflow has no path filter that could strand branch protection.

The required browser gate runs one populated Chromium journey for Player and one for Subtitles. Quick Go tests run on each selected module, including shared packages. Full race/coverage and browser suites run every Monday and on manual deep dispatch. This consciously delays detection of data races, coverage regressions, Firefox/WebKit defects, and non-smoke browser regressions until a deep run; quick tests, lint, security, and production-container checks remain required before publication. A regression that escapes the smoke gate should become a focused smoke assertion when it covers a common deployment path.

The local commit hook checks the staged source-file cap and renews the current worktree lease; pre-push checks the pushed revision's cap and renews that lease. `make worktree-audit` still reports inactive checkouts, but unrelated expired leases do not block a different task's commit or local verification. The revised pre-commit path took 0.84 seconds in this worktree; hosted checks remain separate.

Installer signature verification follows the new reusable `publish.yml` identity and unified `release.yml` identity. [Fulcio's GitHub identity documentation](https://docs.sigstore.dev/certificate_authority/oidc-in-fulcio/) derives the certificate URI from `job_workflow_ref`; [GitHub documents](https://docs.github.com/en/actions/how-tos/secure-your-work/security-harden-deployments/oidc-with-reusable-workflows) that this claim names the called workflow.

Image signatures now live in the public `ghcr.io/kinosail/kinosail-signatures` package, while GitHub stores provenance attestations through its API. [Sigstore supports a separate signature repository](https://github.com/sigstore/cosign/blob/main/README.md); its digest-based fallback tags were appearing as newer, non-runnable versions in each app's GHCR package. Publication verifies each signature with anonymous registry access before tagging an image as deployable. Installers check the separate package first and retain verification against the original app package for already-published images.

Swift CodeQL runs weekly because the last hosted scan took about 65 minutes before cancellation. Player native changes still require an Apple build before merge. This is an explicit delay in Swift security findings; it is not pre-merge Swift scanning. Expensive quality metrics also run weekly.

The latest observed main run spent 61 minutes in the previous publication preflight polling for other workflows, then failed ([run 35660487392](https://github.com/Kinosail/kinosail/actions/runs/35660487392)). The new publication path consumes the five results from its own run, eliminating that poll. It still builds and scans the final two-architecture image after main CI, because that exact digest must pass before promotion. The reusable app suites no longer wait on a separate selection runner.

No end-to-end runtime improvement is claimed from local checks. Measure queue, execution, and publication time across at least 20 successful runs per scenario before setting or claiming a speed target. Preserve separate evidence for source tests, browser checks, image publication, deployed revision, health, TLS, and physical devices.

The 2026-10-14 cache audit retained Go module/build caches, Bundler caches, and Docker layer caches. It added pnpm stores for tooling, web checks, browser journeys, and diagnostics; npm downloads for documentation; and Gradle caches for Android, Wear, and Kotlin CodeQL. Keys use each consumer's lockfile or Gradle build and wrapper properties. Installs and checks still run on cache hits; misses download dependencies normally. The existing setup actions manage these caches ([Node caching](https://github.com/actions/setup-node#caching-global-packages-data), [Java caching](https://github.com/actions/setup-java#caching)). Browser binaries remain uncached because [Playwright advises against caching them](https://playwright.dev/docs/ci#caching-browsers). Hosted cache hits and timing improvements require separate run evidence.

The 2026-10-15 audit measured 31 green main runs at 37 minutes average. One serial job, the Player populated Chromium browser, took 28 to 36 minutes; every other job finished within 6 minutes. Only 10 of those minutes were the Playwright smoke. The rest were eleven HLS proof scripts wired as serial steps, plus one Go test. The proof scripts now run from `scripts/ci/proofs.json` through `scripts/ci/proof_shard.py` as independent `proofs` matrix jobs in `app.yml`, five for Player and three for Subtitles, each with its own timeout and evidence artifact. A failing command skips the rest of its shard unless the manifest marks a later command `always`; other shards keep running. The certified first-fragment Go test moved into the Go tests job for quick runs. The required app check now expects `proofs` and still fails closed. Hosted timing after the split needs its own run evidence.
