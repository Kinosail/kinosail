# Repository audit, 2026-10-14

Audited revision: `7ae7234a` (main after PR #618), worktree `mikeo/repo-audit-c41785`.

## Summary

The Go code is defensive and consistent: every module builds and vets clean, `govulncheck` reports no reachable vulnerabilities, all three module test suites pass, request bodies and outbound responses are bounded, SQL is parameterized, cookies carry `HttpOnly`/`Secure`/`SameSite`, passwords use argon2id, and session tokens are stored hashed. No authorization bypass, path traversal, injection, or data race was found. The serious problems are structural: duplicated application code between Player and Subtitles, a cache-busting scheme that serves stale CSS and JavaScript as immutable, committed test-instance state including TOTP secrets, 210 MB of QA evidence tracked in git, lint and formatting debt hidden by `--new-from-rev`, and 108 shipped locales of which 88 are mostly English. The independent reviews add a handful of medium security and reliability defects at package seams: replayable TOTP codes, an unlimited SSO second-factor step, a request limiter that fails closed, unthrottled trickplay generation, the database closing at the start of the HTTP drain, and filesystem I/O under the global HLS lock.

Recommended order: findings 1 and 3, then the medium items in the three review sections, then 2, 5, 6.

Severity scale: **High** = user-visible defect or security exposure; **Medium** = correctness or maintenance risk; **Low** = hygiene.

## Findings

### 1. High: stale stylesheet served as immutable for a year

`apps/player/internal/server/assets.go:157` sends `Cache-Control: public, max-age=31536000, immutable` whenever a static URL has a `?v=` query. The version is a hand-typed string per template. Player templates reference five different values for the same stylesheet (`skeleton-3` in 36 templates, `media-titles-1`, `electric-20`, `speed`, and 10 with no version); Subtitles templates reference nine (`electric-1` in 57 templates, plus `46`, `64`, `66`, `81`, `cinema-17-buffer-1`, `electric-3`, `impeccable-1`).

`packages/webassets/static/player-app.css` changed 28 times since `skeleton-3` was introduced on 2026-09-25. A returning browser that already cached `app.css?v=skeleton-3` will not revalidate for a year, so most Player pages render with CSS up to three weeks stale after an update.

The script bundle is worse. Player templates load `main.kinosail.bundle.js` under five versions at once (`12-htmx4` in 8 templates, `32-htmx4`, `33-htmx4`, `37-htmx4` in 4, `settings-3-htmx4`); Subtitles under four (`7-htmx4` in 7 templates, `16`, `17`, `21`). `theme.js` is `electric-1` in 31 Player templates and `electric-2` in one. A browser that visited a `v=12` page keeps running a bundle 25 revisions old on that page while the `v=37` pages run the current one, so behaviour differs by page until the cache is cleared.

Eight `strings.Replace(x, "/static/app.css?v=electric-1", "/static/app.css?v=electric-1", 1)` calls in Player (`mfa.go:82`, `passkeys.go:26`, `profiles_http.go:17`, `settings_connection_http.go:29`, `settings_http.go:52`, `settings_http.go:60`, `viewing_import_http.go:21`) and in Subtitles are no-ops left over from an earlier bump; gocritic flags them as `dupArg`.

Fix: derive one version from a content hash of the embedded asset at init (or the build revision) and inject it through the template function map. Delete the per-template literals and the no-op replacements.

### 2. High: Subtitles ships most of the Player server

`apps/player/internal/server` and `apps/subtitles/internal/server` share 209 file names. 92 are byte-identical and 49 more are over 90% similar, about 4,500 duplicated lines, including `album.go`, `home.go`, `collection.go`, `downloads.go`, `hardware.go`, `api_media.go`, `backup_manager.go`, and `auth_login.go`. `internal/configuration` has 7 more identical files. Subtitles registers 236 HTTP routes to Player's 241, including `/watch/{id}`, `/hls/{id}/{file...}`, `/album/{id}`, playlists and smart playlists, continue-watching, DLNA, Jellyfin compatibility, and Home Assistant pairing.

Consequences: every auth or playback fix has to land twice; the Subtitles attack surface includes playback and download endpoints that a subtitle tool does not need; `AGENTS.md` states that adapters call shared operations, which is not what the tree does. PR #618 inventoried the Subtitles routes and plans removal; this audit confirms the scale.

Fix: finish the route removal, then move the remaining identical adapter files into `packages/` with app-specific configuration rather than copies.

### 3. High: committed test-instance state with live TOTP secrets

`apps/player/.kinosail-test-ui-check4/` and `apps/subtitles/.kinosail-test-ui-check4/` are tracked (initial commit 2026-09-15). Each contains a `totp-secret` file holding a distinct 32-character base32 secret generated by `scripts/test-instance.sh` through the real `/api/v1/setup` endpoint, plus fixture media (`LiveTV/test-channel.mp4`, TMDB fixture responses). `.gitignore` only excludes `.kinosail-test/`, so any `KINOSAIL_TEST_ROOT` named differently leaks. `gitleaks` does not flag base32 strings, and `.gitleaksignore` does not mention these paths.

Impact is bounded because the instances are disposable, but these are real credentials in a source-available repository, and the pattern will recur.

Fix: `git rm -r` both directories, add `.kinosail-test*/` to both app `.gitignore` files, and rotate or discard the test instances that used those secrets.

### 4. Medium: 210 MB of QA evidence tracked in git

`engineering/qa` is 210 MB (480 PNG, 50 Playwright `trace.zip`, 598 JSON, 48 HTML including minified Playwright service-worker bundles). `apps/subtitles/engineering/qa` adds more, including `.verification/campaign-proof` output that the root `.gitignore` is meant to exclude. Several PNGs exceed 2 MB; the largest JSON is 8 MB. This slows clones and CI checkouts, and the minified bundles pollute every repository-wide grep (three greps in this audit returned over 700 KB of noise from them).

Fix: keep evidence manifests and checksums in git, move binaries to Git LFS or release/CI artifacts, and extend `.gitignore` with `**/.verification/`.

### 6. Medium: 108 locales, 17 translated

Each app embeds 108 `active.*.json` catalogs and offers them through `localization.SupportedLanguages()`. For 88 of 105 non-English locales, 88% of strings are byte-identical to English (`scripts/generate-locales.py` fills missing entries with the English source). Only ar, de, es, fr, it, ja, ko, nl, pl, pt-BR, pt-PT, ru, sv, tr, uk, zh-Hans, and zh-Hant have more than half their strings translated. A viewer who selects Zulu or Vietnamese gets an English UI with a handful of translated labels.

Fix: offer only locales above a coverage threshold, or label partial locales as such in the picker.

### 7. Medium: Subtitles CSS is produced by a hand-written patch applier at init

`packages/webassets/styles.go` builds `SubtitlesCSS` by applying `subtitles-app.css.patch` (a unified diff with absolute hunk line numbers) to `player-app.css` using a custom patch implementation, and panics on mismatch. Both apps import this package, so a Player CSS edit that shifts the hunk context can make both binaries panic at startup rather than fail a build. Tests cover the current pair, but the design couples two apps' stylesheets through line offsets.

Fix: check in `subtitles-app.css` as a real file and diff it in a test, or express the override as appended CSS rather than a patch.

### 8. Low: dead nested workflow files

`apps/player/.github/workflows/hygiene.yml` and `apps/subtitles/.github/workflows/hygiene.yml` (identical) sit under app directories. GitHub only runs workflows in the repository root `.github/workflows`, so these never execute, use `runs-on: ubuntu-latest` and `go-version: stable` contrary to the root workflows' pinning, and will drift.

### 11. Low: duplicated top-level app scaffolding

### 12. Low: supporter activation trusts the first key the endpoint returns

`packages/supporter` verifies grant certificates with ed25519 and supports pinning through `Config.TrustedPublicKey`, but neither app sets it (`rg TrustedPublicKey apps/` matches nothing outside `packages/`). `service.go:133` therefore accepts whatever public key the activation endpoint at `https://kinosail-supporter-prod.pvw-7m4q2x9.workers.dev` returns on first activation and pins it in state afterwards. Transport is HTTPS with redirects refused, and the grants only unlock cosmetic supporter badges, so the exposure is small; still, the pin exists and should be set to the production key.

### 13. Info: one recent main CI failure was a Trivy scan

Run 38666955326 (2026-10-15 01:40) failed only in the Subtitles production-container Trivy step; the next push passed. The Containerfiles pin the Debian digest and assert minimum package versions, so a newly published CVE in the base image blocks publication until the pin moves. This is a deliberate tradeoff, but it means `main` publication can go red with no code change.

## Independent review results

Three read-only reviews ran in parallel over the identity surface, the filesystem/media/subprocess surface, and concurrency/persistence. Findings below were re-read at the cited lines before inclusion.

### Concurrency, persistence, lifecycle

No data race, deadlock, or non-atomic multi-document write was found. Lock ordering is one-directional (`startup.mu → hls.mu`; `viewing.Manager.mu → catalog PersistMutex → Mutex → ListMutex`), every store persists before committing to memory, HLS jobs cancel and `Wait` their ffmpeg children, and watchroom/liveevents channels are closed under lock exactly once.

- **Medium: SQLite closes at the same instant the HTTP drain starts.** `apps/player/internal/server/application_init.go:25` closes the state database in a goroutine on `lifecycle.Done()`. `packages/appcli/command.go:117-128` derives that lifecycle from `signal.NotifyContext` and uses the same context to start `http.Server.Shutdown` with a 25 s drain. On SIGTERM, every handler still running during the drain hits `sql: database is closed`; a progress save in flight is lost and the viewer sees a 500, and MCP calls fail authentication because `VerifyToken` persists `LastUsed` on each request. Fix: close the database after `Shutdown` returns, not on the signal.
- **Medium: filesystem I/O under the global HLS mutex.** `hls_job.go:55-67`, `hls_seek.go:165-207`, and `hls_startup_completion.go:31-44` run `os.RemoveAll` of stale cache directories, `os.Stat`, policy validation, and atomic file writes while holding `hlsManager.mu`. On slow cache storage one viewer's cache cleanup stalls every other playlist and segment request plus startup preparation. Fix: record an in-progress marker under the lock, do the I/O unlocked, re-validate before publishing the job.
- **Low: every MCP request writes state under `connections.mu` and maps a save failure to `invalid_token`** (`packages/mcpgateway/connections_tokens.go:155-177`). Clients may discard valid grants on a transient disk error. Persist `LastUsed` at a coarse cadence and keep returning the valid token on save failure.
- **Low: `updatecontrol.Store.View` reloads from SQLite on every page render** (`control.go:92-97`, `checker.go:76-91`) and swallows the error at `checker.go:86`.
- **Low: `auditjournal.Journal.Record` copies the whole event slice per event and holds the lock across `fsync`** (`journal.go:95-120`).
- **Low: `remoteaccess.Manager.Serve` leaks one goroutine per listener restart** (`transport.go:109-112`); use `context.AfterFunc`.
- **Low: MCP STDIO over-capacity rejection blocks the accept loop up to 1 s per attempt** (`stdio.go:186-191`); same-user socket only.
- **Info: `busy_timeout` and `synchronous` PRAGMAs are set on one pooled connection** (`documentdb.go:92-105`, `initialize.go:53`). With `SetMaxIdleConns(0)` in CLI update mode later connections rely on driver defaults, which happen to be safe. Move them into the DSN.

### Identity and authentication

No Viewer-to-Owner or unauthenticated-to-authenticated bypass was found. Route allow-lists, session binding to profile revision, OIDC state/nonce/PKCE/issuer checks, SAML `InResponseTo` and issuer binding, SCIM constant-time bearer comparison, legacy cookie migration, and session invalidation on password reset, profile removal, and SCIM disable were all traced and fail closed. The weaknesses cluster in second-factor hygiene and availability.

- **Medium: TOTP codes replay within the window.** `packages/identitycore/mfa.go:108-134` accepts counter-1, counter, and counter+1, and nothing stores the last accepted counter, so one observed code is valid for about 90 s and any number of submissions. Consumers include password login, REST login, SSO `/login/mfa`, and MFA disable (`DELETE /api/v1/me/mfa`), which needs only a code. An attacker who sees one code and holds the password can sign in and remove the second factor with the same code. Fix: persist a last-counter per profile and reject `counter <= last` inside the factor transaction.
- **Medium: SSO second-factor step has no attempt limiter.** `packages/federation/oidc_http.go:116-131` calls `VerifySecondFactor` directly; the Player hook at `profiles_mfa.go:19` applies no limiter, and the challenge lives 10 minutes and is consumed only on success. Password and REST login are limited (30 per IP, 10 per account per minute); this path is not, so an attacker who controls the IdP account can brute-force the 6-digit code on the LAN. Fix: apply the same limiter per IP and per profile and consume the challenge after a few failures.
- **Medium: the request limiter fails closed at 1024 keys with no IPv6 aggregation.** `packages/httpguard/limiter.go:10-38` denies every new key once the map is full and no window has expired. Keys are raw remote hosts, so one IPv6 /64 supplies unlimited keys. A public attacker with 1024 addresses locks every household member on a new IP out of passkey login for renewable 60 s windows. Fix: key IPv6 by /64, evict the oldest window instead of denying.
- **Low/Medium: passkey login ceremonies can be exhausted anonymously.** `packages/passkeys/engine.go:17,195` caps ceremonies at 1024 with a 300 s TTL; `login/begin` is a public route limited only per IP. About 103 addresses fill the map in a minute and block all remote authentication for five minutes.
- **Low: "sign out other devices" revokes every profile's sessions.** `packages/identitycore/sessions.go:261-272` clears the whole map and reinserts the caller. The Owner action logs out every viewer, TV, and Quick Connect session, and leaves API keys untouched. Fix: filter by the caller's profile ID.
- **Low: every authenticated browser request takes the exclusive profile lock and rewrites the session file** (`apps/player/internal/server/profiles_token.go:64-68`, Subtitles `profiles_access.go:88-96`). HLS playback alone causes continuous full rewrites. Fix: update `LastSeen` only when it moved by more than 60 s and use a read lock for lookups.
- **Low: Jellyfin image routes appear in both the remote-deny and remote-allow tables** (`auth_remote_routes.go:44,77,103`); deny runs first, so remote Jellyfin clients get no artwork. Add a disjointness test.
- **Low: the CSRF check is skipped when `User-Agent` is empty** (`apps/player/internal/server/security.go:60`, same in Subtitles). Not exploitable from a browser today; drop the clause.
- **Low: passkey clone warnings are audited but the login still succeeds** (`apps/player/internal/server/passkeys.go:70-74`). Reject or force step-up when `CloneWarning` is set.
- **Info:** `packages/identitycore/api_session.go` returns a fixed `expiresIn` of 2592000 regardless of configured timeouts; Subtitles `setRequireMFA` revokes the Owner's own session while Player revokes selectively.

### Filesystem, media, and subprocesses

Path confinement is centralized and sound: the scanner builds item paths under symlink-resolved roots, `library.VisibleItem` requires `index.Safe`, Subtitles writes only through `os.Root` with `Lstat`, `SameFile`, `O_EXCL` temp files and `Rename` or `Link`, Player never writes inside a library root, archive handling passes `--` before untrusted names, every ffmpeg/ffprobe/whisper/tesseract/fpcalc call places untrusted paths after `-i` or as the final positional, backup restore allowlists entry names and caps decoded size, and provider fetches dial resolved IPs, reject link-local ranges, and cap bodies. The defects are at seams where one package was wired without the guard its siblings use.

- **Medium: trickplay generation has no admission control and races on a fixed temp file.** `packages/playback/trickplay.go:37-71` spawns one ffmpeg seek and decode per uncached 10 s bucket with a 15 s timeout and no governor, unlike `serveEpisodeStill`, which acquires a background workload slot first. `trickplay.go:88` writes to `target + ".tmp.jpg"`, so two concurrent requests for the same bucket truncate each other's output. Any signed-in Viewer, including an API key, can request thousands of buckets in parallel and starve the host with no 429 or 503. Fix: acquire the workload governor before generating, singleflight per target, and use `os.CreateTemp`.
- **Low: media share streaming skips the `Safe` confinement check.** `packages/mediashares/delivery.go:11-29` returns `item.Path` from `index.Find` without `index.Safe`, which every other media route applies through `VisibleItem`. If a library file is replaced by a symlink or a root is removed after scanning, `/media/{id}` returns 404 but a share link still streams the target. Fix: add `Safe` to the share dependencies.
- **Low: absolute library paths leak to Viewers through download job errors.** `packages/downloads/manager.go:235` stores `err.Error()`, which for copy failures is a raw `*os.PathError` with the host path, and `downloads_http.go` renders it. Map to a fixed message and log the real error with the request ID.
- **Low: TMDB artwork is cached under the remote extension and served with an extension-derived type.** `packages/metadata/tmdb.go:187-230` checks only an `image/` Content-Type prefix; `/art/{id}` serves the cached file through `http.ServeFile` with no explicit type. A compromised or Owner-pointed image origin could return HTML cached as `x.html` and served as `text/html` from the Player origin. Allowlist extensions, run `image.DecodeConfig`, and set an explicit image Content-Type.
- **Low: sidecar install and `.hidden` cleanup depend on `link(2)`.** `apps/subtitles/internal/server/subtitle_sidecar_file.go:59-61` and `subtitle_cleanup.go:220-226` use `root.Link` for exclusivity; exFAT, FAT, and some SMB or FUSE mounts reject hard links, so every install fails and cleanup stops partway with a digest that no longer matches the preview. Fall back to `Lstat` plus `Rename` on `ENOTSUP`/`EPERM`/`EXDEV` with a clear message.
- **Low: a malformed `playSessionId` falls through to the raw playlist.** `apps/player/internal/server/hls_playlist_session.go:142-145` returns `false` for an invalid session ID and `:369` then serves the unprojected `.m3u8`, so a non-conforming Jellyfin client gets an EVENT playlist that never ends. Respond 400 instead.
- **Info (unconfirmed):** the planned HLS cache directory name in `packages/playback/hls_recipe.go:236-243` grows with up to 128 omitted ranges and may exceed NAME_MAX; `packages/mediashares/helpers.go:22-33` derives device labels by iterating a map, so labels are nondeterministic.
