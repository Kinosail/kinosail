# Bounded hosted campaign proofs

Local heavy execution is held for native playback priority and disk headroom.
The parent authorized focused R06, Q14 and Q09 proofs on existing GitHub runners.
These are diagnostic proofs, separate from final exact-head protected validation.

Failures to prevent before implementation:

- Manual selection could alter ordinary PR, push, scheduled or merge-group gates.
  Keep CI and its affected selection byte-identical. Extend the existing layout
  workflow only; its default manual and ordinary PR layout paths remain intact.
- An arbitrary selection could execute a command or escape artifact paths.
  Accept exactly R06/Q14/Q09 through a shell case, with fixed driver paths.
- Diagnosis could trigger unrelated layout/media suites. Disable that job only
  for an explicitly selected manual proof; never for PRs or default manual runs.
- Cold prerequisites or compilation could be mistaken for product RED. Bound
  dependency preparation separately; each owned driver distinguishes setup,
  timeout, empty/partial results and actual completed public assertions.
- A successful focused run could be mistaken for protected acceptance. Use a
  distinct job name; ordinary complete selected CI remains required before merge.
- Raw logs, cookies, URLs, bodies, traces or prior evidence could be uploaded.
  Upload exactly four safe JSON files from each fixed per-ID directory. Each
  driver records private evidence hashes and safe results, not raw diagnostics.
- Normal source, driver or overlay could drift during proof. Owned drivers pin
  inputs before and after execution and record the exact checkout revision.
- Browser defaults could retry/flakily pass. Drivers explicitly select Chromium,
  one worker, zero retries, nonzero exact case counts and distinct evidence.
- A timeout could leave a fixture running. Driver deadlines settle the owned
  process group; job timeout is only an outer fallback.

First controls use a fictional Python executable to verify dispatch without
launching Go, Node, browsers, compilation, playback, services or the Mac UI.
Workflow source controls protect the documented boundary that public product
journeys cannot exercise: selection, dependency admission and safe artifact scope.
