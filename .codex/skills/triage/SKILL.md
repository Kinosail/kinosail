# Triage

Use the repository's issue-tracker and label mapping. Treat a specifically named issue or pull request as in scope.

Gather the body, comments, labels, dates, and relevant code. For a pull request, inspect its diff. Search for an existing implementation and contextually similar prior rejections; do not load an entire knowledge base when a focused search answers the question.

Recommend one category (`bug` or `enhancement`) and one state:

- `needs-triage`
- `needs-info`
- `ready-for-agent`
- `ready-for-human`
- `wontfix`

Verify claims where practical through a focused reproduction or relevant tests. Ask focused questions only when missing information prevents a sound disposition.

When the user has authorized the specific triage action, apply labels and add a concise comment. Add an agent brief with independently verifiable acceptance criteria for `ready-for-agent`. Close an issue only when that disposition is authorized. Prefix generated tracker comments with:

> *This was generated by AI during triage.*

Honor explicit state instructions without another interview unless they conflict with existing state or require an unapproved close.
