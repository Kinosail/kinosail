# Wayfinder

Use this for planning work whose route is not yet clear. Do not replace an implementation request with planning.

Create one map whose destination defines completion. Record:

- destination;
- settled decisions with links to their detail;
- precise open decision tickets;
- in-scope questions that are not yet precise enough to ticket;
- explicit out-of-scope work.

Each decision lives in one ticket. Use the tracker's child and dependency relationships when available. Claim a ticket before work so concurrent sessions do not duplicate it.

Resolve the current frontier as far as the user's request requires. Use research, a prototype, or focused questions according to the decision. Record each answer, close its ticket when authorized, update the map, and add newly visible decisions. Do not impose arbitrary token budgets or one-ticket-per-session stops.

Research tickets may run independently when delegation is available. Human preference decisions remain with the user. When the route is clear, produce or hand off to the requested spec or implementation workflow.
