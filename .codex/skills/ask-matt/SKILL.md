# Choose an engineering workflow

Recommend only skills currently available in the session:

- ambiguous product or domain decisions: `domain-modeling` or `grill-with-docs`;
- test-first behavior: `tdd`;
- hard bug or performance regression: `diagnosing-bugs`;
- interface or module design: `codebase-design`;
- throwaway logic or UI question: `prototype`;
- primary-source investigation: `research`;
- branch, pull request, or working-tree review: `code-review`;
- merge or rebase conflicts: `resolving-merge-conflicts`;
- human-only setup steps: `wizard`;
- large decision map: `wayfinder`;
- spec or tickets: `to-spec` then `to-tickets`;
- approved build work: `implement`.

Use the fewest skills that cover the request. Continue in the current context unless isolation has a concrete benefit. Do not invent missing skills, fixed context budgets, or a mandatory idea-to-ship lifecycle.
