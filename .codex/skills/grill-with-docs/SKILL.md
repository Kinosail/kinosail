# Grill with docs

Use this only when the user wants an interview or consequential choices cannot be inferred.

Research factual questions yourself. Ask the user about preferences, tradeoffs, and product intent in small, coherent rounds. Maintain a short list of unresolved decisions and stop interviewing when the work is clear enough to act.

When a domain term becomes settled, update the relevant `CONTEXT.md`. Record an ADR only for a hard-to-reverse, surprising decision made through a real tradeoff. If the `domain-modeling` skill is available, use its formats; otherwise follow the repository's existing conventions.
