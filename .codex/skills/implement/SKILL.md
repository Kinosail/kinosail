# Implement

Complete the requested behavior using the repository's existing seams and policies.

- Resolve acceptance criteria from the supplied spec, ticket, and conversation.
- Use test-first slices when requested or when a regression test is the clearest proof.
- Run focused checks while editing and the repository's affected-change gate before delivery.
- Review the final diff against both the request and repository standards.
- Commit and publish only when the user's request and repository policy authorize it.

Do not introduce a user checkpoint for routine implementation choices. Ask only when missing information materially changes product behavior, scope, or authority.
